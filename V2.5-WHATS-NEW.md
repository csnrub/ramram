# samRAM v2.5 — what changed

## OPSEC audit documentation (`docs/flow-in-depth/`)

Nine new documents written for security auditors who need to know **exactly** what
samRAM does on target computers at the OS / network level — every TCP connection,
every file written to disk, every Windows service created, every kernel driver
loaded, every forensic trace left behind. No Python abstractions — pure Windows
internals and wire-level detail.

| Doc | Covers |
|---|---|
| `01-kerberos-authentication.md` | AS-REQ/AS-REP on tcp/88, ccache handling, DC event log entries |
| `02-ad-enumeration.md` | LDAP bind (SASL/GSSAPI), computer object query, DNS A lookups, per-host tcp/445 SYN probes |
| `03-connectivity-probes.md` | Every probe (DNS, rDNS, ICMP, tcp/445/135/5985/3389/28473) at the packet level |
| `04-full-dump-acquisition.md` | SMB3 session setup, ADMIN$ access, SCM service-exec (`samRAMCapture`), winpmem driver load (Ring 0), physical memory capture, GB-scale image pull, SHA-256 verify, teardown — every file path, registry key, process, event ID |
| `05-live-fileless-deploy.md` | LeechAgent staging to `C:\LeechAgent\`, service-exec launch, winpmem driver, RPC endpoint on tcp/28473, insecure-mode risk |
| `06-live-memory-queries.md` | What each live command reads from physical memory (EPROCESS chains, PEB, handle tables, TCP endpoints), unencrypted RPC channel risk |
| `07-rapid-triage.md` | Same as 05+06 fanned across N hosts — scale amplification, short exposure window |
| `08-teardown-and-cleanup.md` | Process kill via taskkill, file deletion with retries, SHARING_VIOLATION handling, clean vs failed teardown residue |
| `09-detection-and-forensic-footprint.md` | Consolidated IOC reference — every service name, file path, process, driver, event ID, NTFS/prefetch artifact, EDR allow-list recommendations |

Each document follows: on-target timeline → network connections → files on disk →
services/processes → drivers → registry → forensic residue → risk assessment.
